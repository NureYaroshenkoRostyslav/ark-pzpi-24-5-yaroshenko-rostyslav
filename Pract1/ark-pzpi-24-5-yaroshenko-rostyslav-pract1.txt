3 ОПИС ВИКОНАНОЇ РОБОТИ
Під час виконання практичного завдання було досліджено ключові стандарти та інструкції з написання чистого коду мовою Swift, зокрема офіційне керівництво Swift API Design Guidelines та гайдлайни Ray Wenderlich.

Основні розглянуті правила оформлення коду Swift:
1. Структура файлів та організація: дотримання принципу «один основний тип на файл», групування логічних блоків за допомогою // MARK:, розмежування прав доступу (private, fileprivate, internal, public).
2. Форматування: використання 4 пробілів для відступів, фігурні дужки за стилем K&R, обмеження довжини рядка до 100-120 символів.
3. Конвенції іменування: UpperCamelCase для типів struct, class, enum, protocol та lowerCamelCase для змінних, констант і методів. Уникання магічних чисел шляхом винесення констант у static let або enum.
4. Документування та коментарі: використання DocC синтаксису (///) з тегами - Parameter, - Returns, - Throws. Видалення «мертвого» та закоментованого коду.
5. Специфічні особливості Swift: надання переваги значущим типам struct перед посилальними class, безпечна розпаковка опціоналів guard let, if let, використання trailing closures.
6. Автоматизація: застосування linter-інструменту SwiftLint та автоматичного форматувальника SwiftFormat для підтримки єдиного стилю в команді.

4 ВИСНОВКИ
У ході виконання практичного завдання було розглянуто стандарти оформлення та структурування програмного коду для мови Swift. Отримано практичні навички застосування Swift API Design Guidelines, документування коду за допомогою DocC та налаштування інструментів статичного аналізу SwiftLint. Проведені дослідження доводять, що дотримання єдиного стилю кодування істотно підвищує читабельність, зменшує кількість помилок на етапі компіляції та спрощує процес Code Review у командній розробці.
